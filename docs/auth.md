# 認証・チーム参加・権限

Firebase Authentication（Spark プラン）のみを使う。Cloud Functions は使わない。

## アカウント

- 個人ごとに **メールアドレスとパスワード** でアカウントを作る（Firebase の Email/Password 認証）
- アカウント作成時に表示名を入力する
- パスワードを忘れたときは Firebase 標準のパスワード再設定メールを使う（無料）
- パスワードの条件：大文字・小文字・数字・記号をすべて含む（クライアントで検証する。サーバー側の強制方法は `docs/decisions.md` の未決事項を参照）

## チームへの参加（Setlog 方式）

1. 管理者が設定タブで **参加コード** を表示し、LINE などでメンバーに共有する
2. メンバーはアカウント作成後、参加コードを入力する
3. コードが有効ならその場でチームに参加する（管理者による個別承認はしない）

### 参加コード

- 6 桁の数字に限らない。読み間違えにくい英数字（`0/O`、`1/I/l` などを除く）で 8 文字程度
- 管理者がいつでも **再発行** できる。再発行すると古いコードは無効になり、新しい参加ができなくなる（参加済みのメンバーには影響しない）
- コードはチームごとに一意。発行時に既存コードとの重複を確認する

## 2 回目以降のログイン

- 同じブラウザでは、ログイン状態が保存されているので何もしなくてよい（`browserLocalPersistence`、IndexedDB に保存）
- 別の端末や、ログイン状態が消えたブラウザでは、メールとパスワードでログインする
  - 所属チームはサーバー側（`users/{uid}.teamId`）で分かるので、**参加コードの入力は不要**

### ログイン状態が分かれるケース

- LINE 内ブラウザ、Safari、ホーム画面に追加した Web アプリは、保存領域がそれぞれ別。どれか1つでログインしても、他ではログインし直しが必要
- iOS Safari は、7 日間開かれなかったサイトの保存データを消すことがある
- 対策：共有リンクに `?openExternalBrowser=1` を付け、LINE から開いても Safari が起動するようにして、利用するブラウザを1つにまとめる
- Google ログインは LINE 内ブラウザでブロックされるため採用しない

## チームの作成

- チームに所属していないログイン済みユーザーは、チームを作成できる
- 入力：チーム名
- 作成した人がそのチームの最初の管理者になる。参加コードは自動で発行する
- MVP では **1 人が所属できるチームは 1 つ**

## 権限

| 操作 | 管理者 | メンバー |
| --- | --- | --- |
| 予定の閲覧・出欠の回答・メモの書き込み | ○ | ○ |
| 予定の作成・編集・削除 | ○ | 設定で「全員」のときのみ |
| 用具の追加・編集・削除、自分が持つ・手放す | ○ | ○ |
| 他人が持っている用具を強制的に手放させる | ○ | × |
| 参加コードの表示・再発行 | ○ | × |
| チーム設定の変更 | ○ | × |
| 管理者権限の付与・解除 | ○ | × |
| チーム名の変更 | ○ | × |
| メンバーの登録削除（引退・退部など） | ○ | × |
| 自分がチームを離れる | ○（最後の管理者を除く） | ○ |

- 管理者は他のメンバーを管理者にできる
- 管理者が 0 人になる操作（最後の管理者が自分の権限を外す・チームを離れる、最後の管理者を登録削除するなど）はできない
- チームを離れた人・登録削除された人は `users/{uid}.teamId` が空になり、次に開いたときは参加コードの入力画面になる。持っていた用具は手放した状態になる
- 権限の強制はすべて Firestore セキュリティルールで行う（`docs/data-model.md`）
