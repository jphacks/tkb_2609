# 認証・チーム参加・権限

Firebase Authentication（Spark プラン）のみを使う。Cloud Functions は使わない。

## アカウント

- 個人ごとに **メールアドレスとパスワード** でアカウントを作る（Firebase の Email/Password 認証）
- **登録したメールアドレスの確認**（#39）：登録の直後に Firebase の確認メールを送る（無料）。リンクを開いて確認が済むまでは、「メールアドレスを確認してください」の画面だけを表示し、チームの作成・参加などはできない。画面から確認メールの再送・確認状態の読み直しができ、メールアプリから戻ったときも自動で読み直す
  - セキュリティルールでも、チームに関わる操作（参加コードの照会、チームの作成・参加、チームのデータの読み書き）は `request.auth.token.email_verified == true` の利用者だけに許可する。自分のプロフィールの作成・読み取り・表示名の変更は確認前でもできる
  - 確認後は ID トークンを更新してから先へ進む（ルールが参照する `email_verified` を新しいトークンに反映するため）
  - モックではメールを送れないため、すべてのアカウントを確認済みとして扱う
- アカウント作成時に表示名を入力する
- **Google アカウントでのログイン**（#31）：ログイン画面と登録画面の「Google でログイン／Google で登録」から。初回は登録も兼ねる
  - ポップアップ方式（`signInWithPopup`）。リダイレクト方式は iPhone の Safari でストレージの分離により失敗することがある。ポップアップがブロックされないよう、ボタンを押した直後に開く
  - Google のログイン画面には「bukatsu20261024.web.app に移動」と表示される（開いているサイトと同じアドレスにして、不安を減らすため）。「BUKATSU」と表示するには Google のブランドの確認が必要
  - 表示名の初期値は Google アカウントの名前。チームでの名前は参加・作成時に入力する（従来どおり）
  - Google が確認済みのメールアドレスなので、確認メールは不要（`email_verified` が true）
  - ログイン画面を閉じた場合はエラーを出さない。ポップアップがブロックされた場合は、許可するよう案内する
  - **LINE などのアプリ内ブラウザ**では Google がログインをブロックする（`403: disallowed_useragent`）。ボタンの代わりに案内を出し、LINE では `?openExternalBrowser=1` を付けたリンクで外部ブラウザを開けるようにする。メールとパスワードのログインはそのまま使える
  - **同じメールアドレスでの併用**：Firebase の「1つのメールアドレスに1つのアカウント」の設定のまま使う
    - メールとパスワードで登録し、**メールアドレスを確認済み**の人が同じ Gmail で Google ログインすると、同じアカウントに Google が追加される（所属チームもそのまま。パスワードでも引き続きログインできる）
    - **未確認**のまま Google ログインすると、Firebase の仕様でパスワードが無効になり、Google のアカウントとして扱われる。未確認のアカウントはチームを使えない（#39）ため、失われるデータはない。他人のメールアドレスで先に登録されても、本人が Google で取り戻せる
    - Google で登録した人がメールとパスワードで登録しようとすると「すでに登録されています。Google で登録した場合は「Google でログイン」を使ってください」と表示する。パスワードを使いたい場合は「パスワードを忘れた場合」から設定できる
  - モックでは Google の画面を出さず、`google-user@example.com`（Google 太郎、チーム未所属）でログインしたことにする
  - パスワードポリシー（#5）は Google ログインには関係しない
- パスワードを忘れたときは Firebase 標準のパスワード再設定メールを使う（無料）
- パスワードの条件：8文字以上で、大文字・小文字・数字・記号をすべて含む
  - **サーバー側**：Firebase Authentication のパスワードポリシーで強制する（本番 `bukatsu20261024` で「必須」に設定済み。Spark プランで利用可能）。「ログイン時に強制的にアップグレード」もオンのため、条件を満たさない古いパスワードではログインできず、パスワード再設定が必要になる
  - **クライアント側**：同じ条件を `src/lib/password.ts` で検証し、登録画面に条件を表示する。記号は Firebase が認める30文字（`^ $ * . [ ] { } ( ) ? " ! @ # % & / \ , > < ' : ; | _ ~ ` -`）だけを数える
  - エミュレータには本番のパスワードポリシーは適用されない
- ログイン画面・登録画面のパスワード欄は、右端の目のボタンで表示・非表示を切り替えられる（#33、`src/components/PasswordInput.tsx`）。初期状態は非表示。切り替えても入力中の文字・カーソル位置・キーボードはそのまま。`autoComplete` は変えず、パスワード管理機能の自動入力・保存が引き続き働く。送信するときは非表示に戻す（表示のまま送ると保存が提案されないことがあり、失敗時に見えたままになるため）

## チームへの参加（Setlog 方式）

1. 管理者が設定タブで **参加コード** を表示し、LINE などでメンバーに共有する
2. メンバーは参加コードと、このチームでの名前を入力する
3. コードが有効ならその場でチームに参加する（管理者による個別承認はしない）

### 参加コード

- 6 桁の数字に限らない。読み間違えにくい英数字（`0/O`、`1/I/l` などを除く）で 8 文字程度
- 管理者がいつでも **再発行** できる。再発行すると古いコードは無効になり、新しい参加ができなくなる（参加済みのメンバーには影響しない）
- コードはチームごとに一意。発行時に既存コードとの重複を確認する

## 2 回目以降のログイン

- 同じブラウザでは、ログイン状態が保存されているので何もしなくてよい（`browserLocalPersistence`、IndexedDB に保存）
- 別の端末や、ログイン状態が消えたブラウザでは、メールとパスワードでログインする
  - 所属チームはサーバー側（`users/{uid}.teamIds`）で分かるので、**参加コードの入力は不要**

### ログイン状態が分かれるケース

- LINE 内ブラウザ、Safari、ホーム画面に追加した Web アプリは、保存領域がそれぞれ別。どれか1つでログインしても、他ではログインし直しが必要
- iOS Safari は、7 日間開かれなかったサイトの保存データを消すことがある
- 対策：共有リンクに `?openExternalBrowser=1` を付け、LINE から開いても Safari が起動するようにして、利用するブラウザを1つにまとめる
- Google ログインは LINE 内ブラウザでブロックされる。LINE で開いた場合は Google ログインの代わりに外部ブラウザで開くよう案内する（#31）

## チームの作成

- ログイン済みユーザーは、所属済みでもチームを追加作成できる
- 入力：チーム名、このチームでの名前
- 作成した人がそのチームの最初の管理者になる。参加コードは自動で発行する
- 1 人が複数のチームに所属できる。上部の選択欄で切り替え、「チームを追加」から参加・作成する

## 権限

| 操作 | 管理者 | メンバー |
| --- | --- | --- |
| 予定の閲覧・出欠の回答・メモの書き込み | ○ | ○ |
| 予定の作成・編集・削除 | ○ | 設定で「全員」のときのみ |
| 用具の追加・編集・削除、自分が持つ・手放す | ○ | ○ |
| 他人が持っている用具を強制的に手放させる | ○ | × |
| 参加コードの表示・再発行 | ○ | × |
| チーム設定の変更 | ○ | × |
| 管理者権限の付与・解除 | ○ | × |
| チーム名の変更 | ○ | × |
| チームそのものの削除（最後の管理者も可） | ○ | × |
| メンバーの登録削除（引退・退部など） | ○ | × |
| 自分がチームを離れる | ○（最後の管理者を除く） | ○ |

- 管理者は他のメンバーを管理者にできる
- 管理者が 0 人になる操作（最後の管理者が自分の権限を外す・チームを離れる、最後の管理者を登録削除するなど）はできない
- チームを離れた人・登録削除された人は `users/{uid}.teamIds` から対象チームだけが外れる。他の所属があればそのチームへ切り替え、未所属なら参加画面になる。持っていた用具は手放した状態になる
- 権限の強制はすべて Firestore セキュリティルールで行う（`docs/data-model.md`）

## Firebase 版の複数所属とチーム削除（#24）

Firebase 版も複数チームの参加・作成・切り替え、チーム別表示名とチーム削除に対応する。所属上限は20チーム。アカウント名とチーム内の名前は別に保持する。管理者の除名・削除操作は対象チームを選択して実行する。

チーム削除を開始すると、開始した管理者の画面にだけ「削除を再開」を表示する。ほかのメンバーは、削除が完了して所属が外れるまで通常どおりチームを使える（削除中に止めるのは新規参加と参加コードの発行のみ）。途中で通信が切れた場合は、開始者がログインして同じチームを開き再開する。削除の完了後は購読を張り直し、残りのチーム（なければ参加画面）を表示する。取り消しはできない。
