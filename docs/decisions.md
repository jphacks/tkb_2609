### 初期設計メモからのおもな変更点（Ver.1.0）

| 初期設計メモ | Ver.1.0 | 理由 |
| --- | --- | --- |
| 参加時、チームのメアドに承認メールを送る | 管理者が共有した参加コードを入力すると即参加（Setlog 方式）。コードは再発行可能 | メール送信には Cloud Functions（有料プラン）が必要なため |
| 個人はパスワードを打たない | 個人ごとにメール・パスワードでアカウントを作る | 別の端末でもログインでき、所属チームを自動で判別できるため |
| チームコードは 6 桁 | 6 桁の数字に限らない英数字 | 読み間違えにくく、推測されにくくするため |
| 部活ごとのパスワード（作成者が決める） | 廃止。強度条件（大文字・小文字・数字・記号）は個人のパスワードに適用 | 参加コードと役割が重なるため |
| 何秒ごとに更新するかを決める | 一定間隔での取得はせず、変更を自動で受け取る | Firestore のリアルタイム機能で足りるため |
| 自分の用具の状態のみ変更可 | 加えて、管理者は他人の用具を強制的に手放させられる | 持っている人が来ない・退部した場合のため |
| 全員が書けるメモ欄 | 1 件ずつ積み上げる形式 | 同時に書いたときに内容が消えるのを防ぐため |

## 決定事項

| 日付 | 決定 | 理由 |
| --- | --- | --- |
| 2026-10-24 | Firebase Spark プランのみ使い、Cloud Functions は使わない | 完全無料で作るため |
| 2026-10-24 | 個人ごとにメール・パスワードでアカウントを作る | 2 回目以降、別の端末でもメールとパスワードだけでログインでき、所属チームを自動で判別できるため |
| 2026-10-24 | 参加は Setlog 方式（管理者が共有した参加コードを入力すると即参加）。コードは再発行できる | メール送信には Cloud Functions が必要なため。コードの再発行で、意図しない参加を止められる |
| 2026-10-24 | 参加コードは 6 桁の数字に限らない | 読み間違えにくい英数字にして、推測もされにくくするため |
| 2026-10-24 | Google ログインは使わない | LINE 内ブラウザでブロックされるため |
| 2026-10-24 | 出欠の未回答は「出席」として扱い、区別しない | 仕様どおり。回答の手間を減らすため |
| 2026-10-24 | 出欠は予定のドキュメントの中に持つ | 読み取り回数を無料枠内に収めるため |
| 2026-10-24 | 「持つ」ボタンは誰も持っていない用具に表示。1 人が複数の用具を持てる | 複数の用具を持つ前提のウィジェット仕様と合わせるため |
| 2026-10-24 | 一定間隔での取得はせず、`onSnapshot` でリアルタイム更新する | Firestore が変更を自動で届けるため、間隔の調整が不要 |
| 2026-10-24 | 予定のメモは 1 件ずつ積み上げる形式 | 1 つのテキストを全員で編集すると、同時に書いたときに内容が消えるため |
| 2026-10-24 | ~~用具に任意の「よみがな」を持たせる~~ → 2026-10-24 に廃止（PR #16 レビュー） | 入力の手間を減らすため。漢字の用具名はかなの後ろに並ぶ |
| 2026-10-24 | フロントは Vite + React + TypeScript の SPA、Firebase Hosting で配信 | 無料で静的配信でき、Firebase SDK と相性がよいため |
| 2026-10-24 | 部活ごとのパスワードは廃止し、強度条件は個人のパスワードに適用する | 参加コードと役割が重なるため |
| 2026-10-24 | 参加時の管理者承認はしない（コードを知っていれば参加） | メール送信は無料枠では不可。コードの再発行で参加を止められる。必要になればアプリ内承認を追加する |
| 2026-10-24 | 管理者のみ、他人が持っている用具を強制的に手放させられる | 持っている人が来ない・退部した場合に、用具が持たれたままになるのを防ぐため |
| 2026-10-24 | スタイルは CSS Modules ＋ CSS 変数（デザイントークン）。UI ライブラリは使わない | 追加の依存なしで軽く保て、画面ごとにスタイルが閉じるため |
| 2026-10-24 | 画面遷移はルーターを使わず、タブと重ね表示（Layer・Sheet）の状態で管理する | 画面数が少なく、ショートカットや LINE からは常にトップを開くため URL を分ける必要がない |
| 2026-10-24 | 管理者の強制手放しは、用具ごとの「…」メニューの中に置く | 通常の「持つ」操作と見分けがつき、誤操作しにくいため |
| 2026-10-24 | 用具名の重複は不可（全角・半角、大文字・小文字、空白の違いは同じとみなす） | PR #16 レビュー。同じ用具が二重に登録されて所在がわからなくなるのを防ぐため |
| 2026-10-24 | 用具の持ち主の名前は枠の右側にだけ表示し、「誰も持っていません」は表示しない | PR #16 レビュー。表示を減らして一目で見やすくするため |
| 2026-10-24 | 予定の追加時にメモも書ける（最初のメモとして保存） | PR #16 レビュー |
| 2026-10-24 | 管理者がチーム名を変更でき、メンバーの登録削除（引退・退部）ができる。全員が「チームを離れる」を使える。管理者は最低 1 人残す | PR #16 レビュー。離脱・削除時は持っている用具を手放した状態にし、持ち主のいない用具が残らないようにする |
| 2026-10-24 | 予定の一覧は画面の大きさに関わらず 1 列（広い画面では幅 720px で中央） | PR #16 レビュー。日付順に上から追えるようにするため |
| 2026-10-24 | 画面の大きさ・向きに合わせてレイアウトを変える（`docs/ui.md`） | PR #16 レビュー。スマホ縦の使い勝手は変えず、広い画面では一覧を複数列にし、横向きスマホでは縦の高さを確保する |

### 複数チーム所属への変更（2026-10-24）

ユーザー要望により単一所属の制約を廃止する。所属一覧は `teamIds`、現在選択中のチームは `teamId` に保存する。参加・作成時にチーム内の名前を必須入力し、変更はそのチームのメンバー情報と保有用具に限定する。アカウント登録時の名前はアカウント名として保持する。離脱・登録削除は対象チームだけに適用する。今回の実装はモックで、Firestore 実装時もルールによるチーム単位の権限強制を維持する。
