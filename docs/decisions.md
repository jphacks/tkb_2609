### 初期設計メモからのおもな変更点（Ver.1.0）

| 初期設計メモ | Ver.1.0 | 理由 |
| --- | --- | --- |
| 参加時、チームのメアドに承認メールを送る | 管理者が共有した参加コードを入力すると即参加（Setlog 方式）。コードは再発行可能 | メール送信には Cloud Functions（有料プラン）が必要なため |
| 個人はパスワードを打たない | 個人ごとにメール・パスワードでアカウントを作る | 別の端末でもログインでき、所属チームを自動で判別できるため |
| チームコードは 6 桁 | 6 桁の数字に限らない英数字 | 読み間違えにくく、推測されにくくするため |
| 部活ごとのパスワード（作成者が決める） | 廃止。強度条件（大文字・小文字・数字・記号）は個人のパスワードに適用 | 参加コードと役割が重なるため |
| 何秒ごとに更新するかを決める | 一定間隔での取得はせず、変更を自動で受け取る | Firestore のリアルタイム機能で足りるため |
| 自分の用具の状態のみ変更可 | 加えて、管理者は他人の用具を強制的に手放させられる | 持っている人が来ない・退部した場合のため |
| 全員が書けるメモ欄 | 1 件ずつ積み上げる形式 | 同時に書いたときに内容が消えるのを防ぐため |

### Firebase 版での複数チーム所属・チーム削除の扱い（2026-10-24、PR #21 を dev に合わせる際に決定）

複数チーム所属とチーム削除はモックで先に実装し、Firebase 版は当面1人1チームのまま動かす。Firestore のセキュリティルール（#7）は単一所属を前提にしており、複数所属・チーム削除には別途ルールとデータ構造の設計が必要なため。

- `Repository` は複数チーム対応のインターフェースにそろえ、Firebase 版は `teamIds` を現在のチームだけから作る。別チームへの切り替え・2つ目のチームへの参加・チーム削除は「まだ対応していません」と分かるエラーにする
- 参加・作成時の「このチームでの名前」は、Firebase 版ではプロフィールの名前として保存する（1チームのみのため、アカウント名とチームでの名前は同じになる）
- `Repository.supports` で実装ごとの対応機能を示し、未対応の機能（チームの切り替え・追加、チーム削除）は画面に出さない

### 複数チーム所属への変更（2026-10-24）

ユーザー要望により単一所属の制約を廃止する。所属一覧は `teamIds`、現在選択中のチームは `teamId` に保存する。参加・作成時にチーム内の名前を必須入力し、変更はそのチームのメンバー情報と保有用具に限定する。アカウント登録時の名前はアカウント名として保持する。離脱・登録削除は対象チームだけに適用する。今回の実装はモックで、Firestore 実装時もルールによるチーム単位の権限強制を維持する。

### チーム削除・コピー互換性（2026-10-24）

ユーザー要望により管理者がチーム全体を削除できるようにする。最後の管理者も削除できるが、全メンバーに影響し元に戻せないことを確認画面に明示する。対象チームのデータとコードを削除し、全員の所属一覧・選択状態を一度に更新する。今回の実装は localStorage モック。Firestore への実装ではサブコレクションが親削除だけでは消えないため、無料枠の範囲で削除処理と権限ルールを別途設計する。

参加コードのコピーは Clipboard API を優先し、HTTP や権限拒否時には選択テキストのコピーへフォールバックする。自動コピーが拒否されても、読み取り専用のコード欄で選択・長押しによる手動コピーを可能にする。
